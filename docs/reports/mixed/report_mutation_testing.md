# Mutation testing — задача 2.2.9

## Описание

Реализован модуль оценки качества API-тестов. Он изменяет один HTTP-ответ сервиса и проверяет, обнаруживают ли тесты нарушение контракта.

Поддерживаются три оператора: изменение типа данных, удаление обязательного поля и подмена HTTP-статуса. Модуль проверяет применимость мутации, управляет запусками, рассчитывает Mutation Score и сохраняет отчёт. Для Catalogue подготовлен адаптер к штатному Docker-runner.

## Результаты

Проверены пять сохранённых тестов Catalogue и 46 мутаций. Исходные тесты и код команды не изменялись.

| Показатель | Исходные тесты | Отдельный усиленный набор |
|---|---:|---:|
| Обнаружено мутаций | 8 | 46 |
| Пропущено | 34 | 0 |
| Неопределённо | 4 | 0 |
| Mutation Score | 19,05% | 100% |
| Доля оценённых | 91,30% | 100% |

**Mutation Score = обнаруженные / (обнаруженные + пропущенные) × 100%.** Неопределённые исходы исключаются из расчёта и показываются отдельно.

Низкий результат исходных тестов связан с недостаточными проверками типов и обязательных полей ответа. Усиленный вручную набор обнаружил все выбранные мутации; он использовался в дополнительном локальном эксперименте и в сдачу не входит. Его 100% не характеризуют качество текущего генератора или обнаружение любых ошибок.

## Плюсы

- Реализованы три оператора и расчёт метрик.
- Проверяются доставка дефекта, повторяемость результата и восстановление после удаления мутации.
- Оценка сохранённых тестов не требует вызовов LLM.

## Ограничения

- Поддерживается подмножество OpenAPI 3.0 с JSON и локальными ссылками.
- Адаптер проверен на GET-сценариях Catalogue с `requests.Session`.
- Подключение к основному агенту и общему отчёту проекта ещё не выполнено.

## Проверка и запуск

После упрощения полный последовательный Docker-прогон воспроизвёл результат исходного набора: 8 обнаруженных, 34 пропущенных и 4 неопределённые мутации, score 19,05%.

Добавлен небольшой блок параллельного запуска до четырёх независимых мутаций. Две попытки и восстановление каждой мутации выполняются последовательно. **Все 90 проверок прошли**; параллельная обработка записанных наблюдений сохранила все 46 исходов. Живой Docker-прогон после добавления этого блока ещё требуется.

По умолчанию адаптер использует четыре потока. `--workers 1` включает последовательный запуск.

Для запуска нужны Docker/Compose, штатный образ `api-contract-pytest-runner:step5` и Python-зависимости:

```sh
python -m pip install pytest PyYAML openapi-spec-validator==0.9.0 openapi-schema-validator==0.9.0 jsonschema==4.26.0
python benchmark/mutation/catalogue/run.py --build
```

В сдачу входят `mutation.py`, `test_mutation.py`, три файла адаптера Catalogue (`run.py`, `proxy.py`, `worker.py`) и этот отчёт.
